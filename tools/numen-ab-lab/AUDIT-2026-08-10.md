# Numen 代码审计报告（2026-08-10）

范围：已发布的服务端任务终态反馈实现 + `tools/numen-ab-lab` 持久行动大脑代码。
所有修复均通过 TDD（先复现失败，再最小修复），并已同步到仓库副本。

## 发现并修复的问题

### Python（lab 工作区与仓库副本）

| # | 级别 | 问题 | 修复 |
|---|---|---|---|
| P1 | 高 | `execute_tool_exact` 中 `on_dispatched`（task_id 落盘）在 `release_control` **之后**执行；释放失败会吞掉已取得的派发结果，checkpoint 停留在 `tool_planned`，恢复时被当作模糊状态拒绝 | 派发回执先提取 task_id 并调用 `on_dispatched`，再独立释放租约；释放失败不再掩盖结果（租约由服务端 TTL 兜底） |
| P2 | 中 | A/B 运行器 `execute_tool_with_ephemeral_lease` 同样在 `finally` 释放，异常吞掉 dispatch 返回值 | 同 P1 语义：结果先返回，释放失败独立忽略 |
| P3 | 中 | `append_pair` 把 user/assistant 写成两行 JSONL，断电在中间会留下悬空 user（违反“不留下半回合”契约） | 改为单条 `{"messages":[...]}` 事务记录；读取器兼容旧格式 |
| P4 | 中 | `TurnCheckpoint.write` / `save_checkpoint` 只 fsync 文件，不 fsync 目录，rename 在极端断电下可能丢失 | 新增 `fsync_dir`（尽力而为，不支持的文件系统忽略）并在 replace 后调用 |
| P5 | 低 | `McpClient.call` 不检查 MCP `isError` 标记，错误文本可能被当作正常结果 | 检测 `isError` 后 raise，错误文本截断到 500 字符 |
| P6 | 低 | `model_tools` 遇重复工具名静默后者覆盖，模型可见列表可能不一致 | 重复工具名 fail closed |
| P7 | 低 | `safe_segment` 会把 `a/b` 与 `a_b` 折叠到同一路径 | 身份键含 `/` 或 `\` 时直接拒绝 |
| P8 | 低 | 工作区硬编码隔离测试凭据 | 改为环境变量优先、默认值兜底；仓库副本保持无默认凭据 |

### Java（服务端）

| # | 级别 | 问题 | 修复 |
|---|---|---|---|
| J1 | 中 | `ServerApiAgent.execTool` 手动拼接 JSON：`error` 分支的 `detail` 未转义（detail 可含用户可控内容如 `task_id`），`done` 分支只替换双引号不处理反斜杠 → 模型可能读到非法 JSON | 统一为 `jsonResult()`（Gson `JsonObject` 构造）；`idle` 分支的 dispatch 也改为解析后嵌入 |
| J2 | 中 | `ChatTool` 回复 JSON 手动拼接，`text.replace("\"","'")` 无法处理反斜杠/换行/控制字符 | 改用 `TaskResult.ok/fail`（`toJson()` 由 Gson 正确转义） |
| J3 | 低 | `ServerMcpServer` 若干响应手动拼接（`jstr`、create/acquire 回执）；`resolveCompanion` 对忽略大小写歧义静默选第一个 | 全部改 Gson 构造；名字解析改为精确/模糊都要求唯一，歧义拒绝 |

## 审查确认无问题的点

- `ExternalTaskResultStore`：有界缓存、删除同伴时清理、终态映射正确；主线程访问契约由调用点保证（tick / onMainThread）。
- `LlmTaskChain.drainResults`：外部异步记录在 owner 判断之前保存，服务端同伴不会丢终态。
- `ServerNumenActuatorImpl`：策略/租约/限流/审计链完整；`task_status` 精确 ID 查询语义正确。
- MCP 服务器：Bearer-only、拒绝 query token、拒绝通配绑定、body/batch/depth 上限、限流均保留。
- 测试基线：Python 42/42；Java 服务端子集全部通过；`minecraft-numen` 全量构建通过（ChatTool 编译验证）。
